# Инструкции для агентов

## Изменения через OpenSpec

- Используй OpenSpec change для изменений поведения, функциональности,
  интерфейсов, архитектуры и для существенного рефакторинга.
- Перед реализацией найди подходящий активный change в `openspec/changes/`.
  Если его нет, создай change и подготовь необходимые proposal, specs,
  design и tasks. Согласуй план с пользователем, если реализация ещё
  не была им разрешена.
- Реализуй изменения по tasks, отмечай выполненные задачи и поддерживай
  артефакты change в соответствии с принятыми решениями.
- Используй доступные skills `openspec-propose`, `openspec-update-change`
  и `openspec-apply-change` для соответствующих этапов работы.

## Когда change не нужен

- Правки README, CHANGELOG и другой документации, которые описывают
  существующее поведение, исправляют ошибки или улучшают формулировки.
- Исправления опечаток, форматирования и другие небольшие механические
  правки без изменения поведения, публичных интерфейсов и архитектуры.
- Локальные исправления очевидных ошибок, которые восстанавливают
  поведение, уже описанное в specs, без новых требований и проектных решений.
- Изменения инструкций для агентов, включая этот файл, если они не меняют
  требования к продукту.

Оценивай смысл изменения, а не имя файла: если за правкой документации
стоит новое требование или изменение поведения продукта, используй change.
Не создавай change только ради формальности. Если задача расширилась
за пределы исключений, оформи change перед дальнейшей реализацией.
